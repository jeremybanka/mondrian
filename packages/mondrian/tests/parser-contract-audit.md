# Parser semver contract audit

The parser is an unshipped feature on this branch. Public tests are replayed by Break Check against future implementations, so an assertion belongs there only when its failure represents lost consumer behavior. This audit covers every assertion in the original public parser suite, the added parser option/encryption contracts, and the disposition of the private parser suites. Production parsing, validation, serialization, and visual baselines are unchanged.

## Public assertions

| Assertion family                                                 | Disposition and rationale                                                                                                                                                                                                                                                                                         |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Return type                                                      | Require assignability to `PdfDocument`, allowing a future compatible subtype. Do not require exact TypeScript type identity.                                                                                                                                                                                      |
| Effective PDF version                                            | Retain exact expected versions from the header/catalog semantics.                                                                                                                                                                                                                                                 |
| Existing root, Info, object numbers, generations, and references | Retain identities that exist in the input; callers inspect and edit this object graph. Look objects up by identity, not array position.                                                                                                                                                                           |
| Scalar values and PDF arrays                                     | Retain decoded booleans, nulls, numbers, array contents, and PDF array order. Those are document meaning.                                                                                                                                                                                                         |
| Names and strings                                                | Compare decoded bytes and valid public types. Accept equivalent name/string variants, and compatible `Uint8Array` subclasses. Exact lexical variant selection stays private.                                                                                                                                      |
| Dictionary keys, including `__proto__` and non-UTF-8 bytes       | Retain the associated values without requiring a dictionary prototype or byte-entry position.                                                                                                                                                                                                                     |
| File identifiers                                                 | Retain both identifiers, their order, decoded bytes, and the `PdfHexString` shape required by `PdfDocument.id`. Check independent reader results.                                                                                                                                                                 |
| Serialization determinism                                        | Retain repeatability for the same model. Move equality with the original writer's bytes to private tests. No historical serialization layout is frozen.                                                                                                                                                           |
| Page content and metadata                                        | Retain independent observations of page count, dimensions, rotation, text, title, and author. Do not substitute model self-comparison for these observations.                                                                                                                                                     |
| Binary streams                                                   | Retain all original data bytes, filter meaning, and input-buffer independence for both string and byte-array input. `/Length` remains absent because the public `PdfStreamEntries` type reserves it for serialization.                                                                                            |
| Input representation equivalence                                 | Check the same expected stream bytes for each input form. Complete model equality between the two forms stays private.                                                                                                                                                                                            |
| Independent classic/object-stream writers                        | Retain successful parsing, authoring validation, and independently readable output. Do not freeze compression bytes or retained container counts.                                                                                                                                                                 |
| Incremental revisions and deletions                              | Retain the updated page's identity, generation, and geometry, and the absence of the deleted object. Remove sorted-array and exact-array-length assumptions.                                                                                                                                                      |
| Direct PDF 2.0 Info                                              | Require a reference resolving to preserved title/custom metadata and retain pre-existing objects through rewriting. The newly allocated number, generation, array index, and complete model equality stay private.                                                                                                |
| Parse errors                                                     | Require `PdfParseError` and an integer offset in the original input's coordinate range, including prefix translation during recovery. The truncated-input test must actually observe a throw. Exact detection positions, wording, diagnostic priority, and current unsupported-encryption rejection stay private. |
| Explicit recovery                                                | Require strict-default rejection of the two documented malformed cases, successful explicit recovery, readable output, and applicable structured warning fields. Do not require exact message wording, warning count, or callback order.                                                                          |
| Structural decoding limits                                       | Require failure with insufficient caller-specified budgets and success with sufficient budgets. Intermediate accounting, chunking, and exact boundary arithmetic stay private. Current default values are documented; testing them privately permits compatible increases.                                        |
| Indirect Contents and Info                                       | Require original references to survive and independent readers to recover the intended content and metadata. Private tests cover malformed members and diagnostic details.                                                                                                                                        |
| Unicode dates                                                    | Require valid encoded dates to validate and preserve raw bytes through serialization, checked independently with pdf-lib. Its lack of PDF 2.0 UTF-8 date decoding is not treated as a Mondrian failure.                                                                                                           |
| Nonstandard date preservation                                    | Require strict-default rejection, opt-in warnings and byte preservation, and continued rejection of invalid encodings/types. Match established diagnostic codes/severity without freezing prose, path formatting, or ordering.                                                                                    |
| AES-256 passwords                                                | Require R5/R6 user/owner authentication, default empty-password handling, prepared UTF-8 password bytes, rejection of an incorrect password, and independently readable unencrypted output. Do not freeze encryption-object numbers, graph equality, or the list of unsupported handlers.                         |

## Private assertions retained

| Suite                                   | Why its detailed assertions stay private                                                                                                                                                                       |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `parser-representation`                 | Current string/name variants, byte-identical rewriting, model equality, direct Info allocation, and diagnostic formatting.                                                                                     |
| `parse`                                 | Lexical implementation, exact structural bookkeeping, malformed-input diagnosis, hybrid and object-stream internals, and current unsupported syntax. Public tests cover representative supported capabilities. |
| `parser-filters`                        | Individual codecs, predictor algorithms, checksum verification, malformed filter data, and exact decoder error locations.                                                                                      |
| `parser-limits`                         | Per-filter boundary arithmetic, intermediate output charges, shared budgets, invalid option diagnostics, and early stopping.                                                                                   |
| `parser-numbers`, `parser-size`         | Precision boundaries, token offsets, large flat containers, JavaScript engine limits, and freeze/prototype choices.                                                                                            |
| `parser-references`, `parser-revisions` | Detailed reference-resolution and revision precedence cases, retained bookkeeping, and current external-stream limitations.                                                                                    |
| `parser-validation`                     | Full graph equality, particular diagnostic paths, malformed dates/references, and version boundary cases. Public contracts separately cover imported-data capabilities.                                        |
| `parser-recovery`                       | Exact recovery bounds, callback sequences, offsets within malformed constructs, and unrepairable inputs.                                                                                                       |
| `parser-encryption`                     | Crypt filters, permission records, malformed ciphertext, signature exceptions, object-stream charging, exact graph shapes, and current unsupported handlers.                                                   |
| Browser and visual suites               | Bundler/runtime integration and exact PDFium pixel baselines can evolve without becoming release compatibility promises.                                                                                       |

## Controlled mutation checks

The audit uses temporary wrappers around the built package's exported parser, with no production source changes. Before the cutover, the public suite rejected harmless object reordering, fresh Info-number allocation, diagnostic rewording, and equivalent string variants; it also allowed the truncated-input error to stop being thrown. After the cutover, harmless variants are accepted while the missing throw, incorrect offset coordinates, changed string bytes, missing recovery warnings, ignored caller budgets, and altered existing generations are rejected. The experiment scripts and logs stay outside the committed suite; they establish the assertion boundaries without permanently coupling public tests to mock implementation strategies.
